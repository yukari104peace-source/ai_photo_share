# AI向けプロジェクト概要

## 目的と読む順番

友人同士で旅行や日常の写真を見せ合う小さな写真共有アプリ。初学者が理解しながら実装し、まず自分のパソコンで動かす。

最初に本書、[coding_rules.md](coding_rules.md)、[tasks.md](tasks.md)を読み、着手する機能に応じて以下を参照する。

| 資料 | 詳細の参照先 |
|---|---|
| [requirements.md](requirements.md) | 目的・機能・完成条件 |
| [screens.md](screens.md) | 画面の内容・操作・遷移 |
| [routes.md](routes.md) | URL・HTTPメソッド・エンドポイント・テンプレート |
| [database.md](database.md) | カラム・制約・関係・インデックス |

## 確定した範囲

- FlaskとPeeweeは変更しない。DBはSQLite、画面はJinjaテンプレートと通常のHTMLフォームで実装する。
- 必須：メールによる登録・ログイン・ログアウト、写真投稿、一覧、詳細、自分の投稿の削除、いいね追加・取り消し。
- 名前・ユーザー名・表示名は登録・保存しない。メールアドレスは公開しない。
- メールは前後の空白だけ除去し、大文字・小文字を区別して保存・照合する。
- 一覧・詳細・画像の閲覧はログイン不要。投稿・削除・いいねはログイン必須。削除は投稿者本人のみ。
- 写真は1投稿1枚、JPEG・PNG、5MBまで。キャプションは任意・200文字まで。
- 登録後はログイン画面へ、ログイン・投稿・削除・ログアウト後は一覧へ移動する。
- いいね操作と削除ボタンは詳細画面に置く。一覧はいいね数のみ表示する。いいね後は同じ詳細へ戻る。
- DBは `users`、`posts`、`likes` の3テーブル。登録日時・投稿日時は保存し、いいね日時は保存しない。
- コメントは後の候補。検索・フォロー・投稿編集・ユーザー削除・公開運用・確認メール・パスワード再設定は今回実装しない。

## 既存資料の不一致の扱い

会話で確定した以下を採用する。古い記述を理由に機能を追加・省略しない。

- `screens.md`の登録画面にある「ユーザー名」は採用しない。名前を保存しないという直近の決定に従う。
- `requirements.md`の「投稿詳細は必須としない」は採用しない。詳細を含めた5画面を実装する。
- `requirements.md`でいいねの詳細節が抜けていても、いいねは必須とする。
- その他の矛盾が実装内容を変える場合は、該当箇所を示して質問する。新たなユーザー指示があれば優先する。

## 採用パッケージと保存先

バージョンは [requirements.txt](../requirements.txt) を参照し、理由なく更新しない。

| パッケージ | 役割 |
|---|---|
| Flask・peewee | Web処理・SQLite操作 |
| Flask-Login | ログイン操作・現在ユーザー・ログイン必須の制御 |
| Flask-Session・cachelib | サーバー側セッション。CacheLib方式のファイル保存を使用 |
| Flask-WTF・WTForms・email-validator | フォーム・入力検証・CSRF・メール形式検証 |
| Pillow | 画像内容と形式の検証 |
| python-dotenv | 開発時の環境変数読み込み |
| Werkzeug | パスワードのハッシュ化・照合 |

**ユーザー投稿画像の保存先は、プロジェクト直下の `uploads/` とする。** `static/` に保存しない。

| 場所 | 用途 |
|---|---|
| `uploads/` | 投稿画像。`/uploads/<filename>`で配信 |
| `static/` | CSS・必要なJS |
| `instance/app.sqlite3` | 業務データのSQLiteファイル（既定のファイル名） |
| `instance/sessions/` | サーバー側セッションファイル |
| `.env` | 開発用の秘密情報。Gitに含めない |

## 確定した進め方

前回の4つの質問は、ユーザーの「おすすめでお願いします」により、すべてAを採用する。名前は登録せず、進め方は以下とする。

- 1タスクずつ実装・確認・説明し、次の依頼を待つ。複数タスクを明示して依頼された場合は、その範囲を完了する。
- 各タスクは手動確認を基本とし、必須機能完成後に重要部分の自動テストを追加する。
- 識別子は英語、難しい処理の理由だけ日本語コメントで説明する。
- 縦1列の一覧、自分の投稿の識別表示、パスワード最低8文字と確認欄は既存設計の既定案を引き継ぐ。
- 設計資料が存在することを実装済みと判断しない。実装開始時に現物を確認する。
