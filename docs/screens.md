# 画面設計

## 1. 設計の前提

- FlaskのテンプレートでHTMLを表示する、5画面構成とする。
- 登録・ログインはメールアドレスとパスワードを使用する。
- 投稿一覧と投稿詳細はログイン不要。投稿作成・削除・いいねはログインが必要。
- いいねは必須機能に含め、詳細画面で追加・取り消しを行う。操作後はページを再読み込みする。
- コメント、検索、フォロー、投稿編集の画面は今回作らない。
- `requirements.md`には「投稿詳細は必須としない」という以前の記述と、いいねの詳細節の欠落がある。本設計では、その後の会話で確定した「投稿詳細を含む5画面」「いいねは必須」を採用する。
- 縦1列の一覧、自分の投稿への「自分の投稿」表示、パスワード最低8文字と確認入力は、前回の提案を実装上の既定案として採用する。これらはユーザーが個別に選択した要件ではない。

## 2. 画面一覧

テンプレート名は、Flaskの `templates/` ディレクトリからの相対パスとする。ルートの処理詳細は [routes.md](routes.md) を参照。

| 画面 | 目的 | URL | HTTPメソッド | ログイン | テンプレート |
|---|---|---|---|---|---|
| 投稿一覧（トップ） | 新しい投稿から閲覧する | `/` | GET | 不要 | `posts/index.html` |
| ユーザー登録 | アカウントを作る | `/register` | GET・POST | 不要 | `auth/register.html` |
| ログイン | 登録済みのアカウントで認証する | `/login` | GET・POST | 不要 | `auth/login.html` |
| 投稿作成 | 写真1枚とキャプションを投稿する | `/posts/new` | GET・POST | 必要 | `posts/new.html` |
| 投稿詳細 | 1件の投稿を閲覧し、いいねや削除を行う | `/posts/<int:post_id>` | GET | 不要 | `posts/detail.html` |

## 3. 共通表示

- 共通レイアウトは `base.html` とし、各画面で利用する。
- ヘッダーには、トップへ戻るアプリ名と「投稿一覧」を表示する。
- 未ログイン時は「ユーザー登録」「ログイン」を表示する。
- ログイン時は「投稿作成」と、POSTフォームの「ログアウト」ボタンを表示する。
- 成功・失敗の案内は日本語で表示する。入力エラーはフォーム付近に表示する。
- 投稿者のメールアドレスは一覧・詳細のどちらにも表示しない。自分の投稿にだけ「自分の投稿」と表示する。
- 写真は縦横比を保ち、画面幅からはみ出さないようにする。

## 4. 各画面の内容と操作

### 4.1 投稿一覧

- 投稿を新しい順に縦1列で並べる。
- 各投稿に写真、キャプション（ある場合）、投稿日時、いいね数、「詳細を見る」リンクを表示する。
- 写真または「詳細を見る」を選択すると、その投稿の詳細へ移動する。
- 一覧には、いいねの操作ボタンと削除ボタンを置かない。
- 投稿がない場合は「まだ投稿がありません」と表示する。

### 4.2 ユーザー登録

- メールアドレス、パスワード、パスワード確認の入力欄と「登録」ボタンを表示する。
- パスワード確認は入力間違いを防ぐためのもので、保存しない。
- 必須入力、メールアドレスの形式と重複、パスワードの最低8文字、確認入力との一致を検証する。
- 登録成功後はログイン画面へ移動し、登録完了の案内を表示する。自動ログインはしない。
- 入力エラー時は同じ画面に戻し、メールアドレスは保持する。パスワード類は再入力してもらう。
- 登録済みの人向けにログイン画面へのリンクを置く。

### 4.3 ログイン

- メールアドレス、パスワードの入力欄と「ログイン」ボタンを表示する。
- 認証成功後は必ず投稿一覧へ移動する。投稿作成やいいねから案内された場合も同じとする。
- 認証失敗時は同じ画面にエラーを表示する。パスワードは再入力してもらう。
- ユーザー登録画面へのリンクを置く。

### 4.4 投稿作成

- 写真選択欄、キャプション入力欄、「投稿する」ボタン、一覧に戻るリンクを表示する。
- 写真は1枚必須、JPEG・PNG、5MBまで。キャプションは任意で最大200文字とする。
- 投稿成功後は一覧へ移動する。
- 入力エラー時は同じ画面に理由を表示し、キャプションを保持する。写真は再選択してもらう。
- 未ログインでアクセスした場合はログイン画面へ移動する。

### 4.5 投稿詳細

- 写真、キャプション（ある場合）、投稿日時、いいね数、一覧に戻るリンクを表示する。
- 未ログイン時は「いいねするにはログイン」というリンクを表示する。
- ログイン時は、未いいねなら「いいね」、いいね済みなら「いいねを取り消す」ボタンを表示する。
- いいね追加・取り消し後は同じ詳細画面を再表示し、件数とボタンの状態を更新する。
- 自分の投稿にだけ「削除」ボタンを表示する。押すとブラウザの確認ダイアログを出す。
- 確認でキャンセルした場合は何も送信せず、そのまま詳細にとどまる。削除を確定した場合は削除後に一覧へ移動する。

## 5. 画面遷移

| 操作・きっかけ | 遷移先 |
|---|---|
| 一覧で投稿を選ぶ | 選択した投稿の詳細 |
| 詳細で「一覧に戻る」を選ぶ | 投稿一覧 |
| 登録に成功する | ログイン |
| ログインに成功する | 投稿一覧 |
| ヘッダーで「投稿作成」を選ぶ | 投稿作成 |
| 投稿に成功する／投稿作成をやめて一覧へ戻る | 投稿一覧 |
| 未ログインで投稿作成にアクセスする | ログイン |
| 詳細でログイン案内を選ぶ | ログイン |
| いいねを追加・取り消す | 同じ投稿詳細 |
| 自分の投稿を削除する | 投稿一覧 |
| ログアウトする | 投稿一覧 |

## 6. エラー時の表示

- 存在しない投稿には404、他人の投稿の削除要求には403を返す。
- 共通の `errors/error.html` に理由と一覧へのリンクを表示する。通常の5画面とは別の補助テンプレートであり、専用URLは設けない。
- サイズ上限を超えたリクエストを受け付けられない場合は413を返し、投稿作成へのリンクも表示する。
- CSRF検証に失敗した場合は400を返し、画面を開き直すよう案内する。

## 7. 画面確認の観点

- 未ログインで一覧・詳細を閲覧でき、投稿作成はログインへ案内される。
- 登録後はログイン、ログイン後と投稿成功後は一覧へ移動する。
- 一覧にはいいね数だけがあり、詳細でのみ追加・取り消しできる。
- 自分の投稿詳細だけに削除ボタンがあり、キャンセル時は投稿が残る。
- 入力エラー、投稿ゼロ、存在しない投稿でも次の操作が分かる。
