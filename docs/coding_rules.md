# 実装ルール

## 基本方針

- [ai_context.md](ai_context.md)の確定事項と不一致の解決方針に従う。URL・テンプレートは [routes.md](routes.md)、DB定義は [database.md](database.md)を参照する。
- Flask・Peewee・SQLiteを使用し、採用済みパッケージを活用する。無断で別フレームワーク・ORM・追加機能へ広げない。
- 初版は通常のHTMLフォームで作る。Blueprint、JSON API、非同期通信、大規模な階層分割は導入しない。
- 関数・変数は英語のsnake_case、クラスはPascalCase。画面とエラーは日本語。コメントは難しい処理の理由を日本語で記す。
- 必要なファイルだけを作り、既存の変更を上書きしない。依頼された範囲を実装し、結果を説明する。

## ファイルの役割

| ファイル・場所 | 役割 |
|---|---|
| `app.py` | アプリ生成・拡張機能初期化・ルート処理。テスト用設定を渡せる `create_app` 関数にまとめる |
| `config.py` | 環境変数と保存先設定 |
| `models.py` | DB接続オブジェクトとPeeweeモデル。Flaskアプリをimportしない |
| `forms.py` | 入力欄・入力検証 |
| `image_utils.py` | 画像検証・保存名生成・保存・削除 |
| `templates/` | `base.html` と `auth/`・`posts/`・`errors/` |
| `static/` | CSS・必要なJS |
| `uploads/` | **プロジェクト直下のユーザー投稿画像保存先** |
| `instance/` | SQLiteと `sessions/`。公開配信しない |

パスは起動した場所ではなくプロジェクト位置を基準に解決する。モデル側から `app.py` を参照せず、アプリ生成時にDBを設定して循環importを避ける。

## 認証・秘密情報

- Flask-Loginで現在ユーザーとログイン必須操作を管理する。投稿者・いいねした人はフォーム値ではなくログイン情報から決める。
- Flask-SessionのCacheLib方式とcachelibのファイル保存を使い、セッションデータはサーバー側に置く。ログイン時にセッションIDを更新し、ログアウト時に認証情報を除去する。
- 初版は「ログイン状態を記憶する」機能を設けない。セッションの期限などの設定値は `config.py` にまとめる。
- Werkzeugでパスワードをハッシュ化・照合する。パスワードや秘密鍵をログへ出さない。
- `.env`はpython-dotenvで読み込み、秘密鍵は環境変数から取得する。固定の秘密鍵をコードに書かず、未設定なら起動時に知らせる。
- `.env.example`には変数名と説明だけを書く。DB・セッション・実際の秘密情報・投稿画像はGitに含めない。

## フォームと画面

- Flask-WTFとWTFormsを使い、必須入力・文字数・確認一致・メール形式をサーバー側で検証する。
- 登録・ログイン・投稿・削除・いいね・ログアウトのすべてのPOSTでCSRF対策を行う。
- メールは形式だけを検証し、到達可能性の確認は行わない。前後の空白を除いた元の表記を保存し、小文字化・正規化済み値への置き換えをしない。
- 入力エラーは同じフォームに表示し、パスワード・写真は再入力してもらう。投稿成功などのPOST成功後は設計どおりリダイレクトする。
- Jinjaの自動エスケープを使い、キャプションをHTMLとして扱わない。
- `url_for`でリンク・送信先を生成する。データ変更はGETでは行わない。
- 削除権限はサーバー側で検証する。存在しない投稿は404、他人の投稿削除は403、CSRF不正は400、リクエストサイズ超過は413とする。

## DBと画像

- 外部キーを有効にし、メール・画像名・いいねの組み合わせのユニーク制約をDBにも設定する。
- キャプション未入力は空文字。登録日時・投稿日時はUTCで保存し、日本時間で表示する。
- いいね数は集計し、投稿側に重複保存しない。いいね0件の投稿も一覧に表示する。
- 複数のDB変更はトランザクションでまとめる。制約違反をすべて「重複」と扱わず、原因に応じて処理する。
- DB接続はリクエスト終了時に閉じる。既存DBを無断で削除・初期化しない。テーブル作成と既存スキーマの変更を区別する。
- 画像はPillowで実際に読み込めるJPEG・PNGか検証する。ファイル上限5MBは初版では5×1024×1024バイトと定義し、リクエスト上限はフォームの分を考慮する。
- 保存名はアプリ側で一意に生成する。画像は `uploads/`、DBには保存名のみを記録する。
- 配信は `send_from_directory` を使い、アップロード用ディレクトリ外を公開しない。
- DBのロールバックはファイルを元に戻さない。投稿失敗時の片付けと削除失敗時の記録を別途用意する。

## 確認と報告

- タスクごとに正常操作・入力エラー・未ログイン・権限違反のうち関連する項目を確認する。
- 実装内容、確認したこと、確認できなかったことを短く報告する。未確認の動作を成功と記載しない。
- 各タスクは手動確認を基本とし、必須機能完成後に重要部分の自動テストを追加する。テストは本番用・開発用データを触らない一時保存先を使う。
