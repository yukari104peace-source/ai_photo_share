# 実装タスク

## 運用

- 前提は [ai_context.md](ai_context.md)、実装ルールは [coding_rules.md](coding_rules.md) を参照する。
- 以下は未確認の実装タスクとして未チェックで開始する。着手前に既存コードを確認し、実装と動作確認の両方が終わってから完了にする。
- 各タスク完了時に、変更内容・確認結果・未解決事項を短く記録する。確認できなかった項目は明記する。
- 原則は順番に1タスクずつ進める。以降の機能に必要な空ファイルを先回りして量産しない。

## 必須タスク

- [ ] **T1：設定・共通基盤**
  - 前提：依存関係と既存ファイルを確認する。
  - 作業：Flask、環境変数、SQLite接続、外部キー有効化、CSRF、サーバー側セッション、共通テンプレートを準備する。
  - 完了条件：ローカルで起動できる。秘密鍵未設定なら分かるエラーになる。DB接続を終了時に閉じる。秘密情報・DB・セッションがGit対象外である。

- [ ] **T2：ユーザーと登録**
  - 前提：T1。
  - 作業：`User`、登録フォーム、登録ルート・画面を実装する。DB初期化方法を用意し、既存データを消さない。
  - 完了条件：登録後にログイン画面へ移動する。同一メールの重複は拒否し、大文字・小文字が異なるメールは区別する。名前・平文パスワードを保存しない。
  - 確認：未入力、メール形式不正、短いパスワード、確認不一致、CSRF不正を拒否する。

- [ ] **T3：ログイン・ログアウト**
  - 前提：T2。
  - 作業：認証、現在ユーザー取得、ログイン必須の制御、POSTによるログアウトを実装する。登録から移動できるログイン画面と、認証後の一覧の空表示を用意する。
  - 完了条件：ログイン・ログアウト後は一覧へ移動する。セッションデータは `instance/sessions/` に保存される。ログアウト後は保護された操作を実行できない。
  - 確認：認証失敗、メールの大文字・小文字の違い、未ログイン操作、GETによるログアウト拒否。

- [ ] **T4：投稿データと一覧・詳細**
  - 前提：T3。
  - 作業：`Post`、新しい順の一覧、詳細、存在しない投稿の404表示を実装する。
  - 完了条件：ユーザーと投稿の関係を保存でき、一覧から詳細へ移動できる。閲覧はログイン不要。投稿ゼロの案内がある。
  - 確認：開発用データで複数投稿の順序と詳細を確認する。いいね未実装の段階で固定の件数を本実装として扱わない。

- [ ] **T5：写真投稿・配信**
  - 前提：T4。
  - 作業：画像検証、投稿フォーム、ファイル保存、画像配信を実装する。プロジェクト直下の `uploads/` を使い、この段階で `.gitignore` に除外を追加する。
  - 完了条件：写真1枚と任意のキャプションを投稿し、一覧へ移動して写真を閲覧できる。失敗時に不完全な投稿や不要ファイルを残さない。
  - 確認：JPEG・PNG、5MB制限、写真なし、偽装・破損画像、キャプション0・200・201文字、保存先外へのアクセス拒否。

- [ ] **T6：自分の投稿の削除**
  - 前提：T5。
  - 作業：詳細の削除ボタン、ブラウザの確認、本人確認、DBと画像の削除を実装する。
  - 完了条件：確認後に削除され一覧へ戻る。キャンセルで残る。他人の投稿は直接リクエストしても削除できない。
  - 確認：未ログイン、他人の投稿、存在しない投稿、GET・CSRF不正、画像削除失敗時の扱い。

- [ ] **T7：いいね**
  - 前提：T6。モデルの実装順は `User` → `Post` → `Like`。
  - 作業：`Like`、組み合わせの重複制約、追加・取り消し、件数表示、投稿削除時のCASCADEを実装する。
  - 完了条件：詳細で追加・取り消しができ、一覧には件数だけ表示する。重複要求で件数が増えず、投稿削除で関連いいねが消える。
  - 確認：2ユーザーによるいいね、連続送信、自分の投稿へのいいね、未いいねの取り消し、いいね0件の投稿の表示。

- [ ] **T8：全体確認・手順の記録**
  - 前提：T1〜T7。
  - 作業：既存設計の確認項目を2アカウントと未ログイン状態で実施する。起動・DB初期化・必要な環境変数・手動確認の方法を記録する。
  - 完了条件：登録→ログイン→投稿→一覧・詳細→いいね→削除→ログアウトを確認できる。再起動後もユーザー・投稿・写真が残る。CSRF、権限、エラー表示、Git除外を確認済み。

段階実装中の未実装ページは一時的な案内とし、依存タスク完了時に正式な画面へ置き換える。仮の画面や固定値を完成扱いしない。

## 必須機能完成後の確認タスク

- [ ] **T9：重要部分の自動テスト**
  - 前提：必須機能が完成していること。手動確認後に自動テストを追加するという採用方針に従う。
  - 作業：pytestを開発用依存として追加し、登録・認証・権限・CSRF・画像検証・いいね重複・削除を検証する。
  - 完了条件：テスト専用の一時DB・画像・セッション保存先を使い、利用中のデータを変更せずに実行できる。

コメントなどの追加機能は、この一覧に含めない。
