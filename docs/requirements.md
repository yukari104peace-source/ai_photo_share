# 写真共有アプリ 要件定義

## 1. アプリの概要

FlaskとPeeweeを使い、旅行や日常の写真を見せ合う、インスタグラム風の小さな写真共有アプリを作る。
写真を中心とした投稿一覧を用意し、まずは自分のパソコンで動かす。
インスタグラムの全機能や画面を再現することは目指さない。

投稿の閲覧にはログインを求めない。写真投稿・投稿の削除・いいねにはログインが必要となる。
「誰でも閲覧できる」は閲覧時の認証が不要という意味であり、今回インターネットへの公開は行わない。

## 2. 想定ユーザー

- 旅行の思い出や日常の写真を友人と見せ合いたい人。
- 写真を投稿せず、一覧を見るだけの人。

## 3. 必須機能

以下を小さな単位で順に実装する。いいねも最初の完成版に含める。

### 3.1 ユーザー登録

- メールアドレスとパスワードを入力して登録できる。
- 同じメールアドレスを重複して登録できない。
- 未入力や入力形式の誤りがあれば、理由を画面に表示する。
- ユーザー名の登録や、ユーザー名でのログインは設けない。

### 3.2 ログイン・ログアウト

- 登録済みのメールアドレスとパスワードでログインできる。
- 認証に失敗した場合はエラーを表示する。
- ログイン状態を維持し、ログアウトで解除できる。
- 未ログインで投稿などの操作をしようとした場合は、ログイン画面へ案内する。

### 3.3 写真投稿

- ログインした人が、1投稿につき写真を1枚投稿できる。
- 写真は必須とする。
- キャプションは任意で、最大200文字とする。
- 投稿には投稿者と投稿日時を記録する。
- 入力に問題がある場合は保存せず、エラーを表示する。
- 投稿に成功したら、投稿一覧で確認できる。

### 3.4 投稿一覧

- ログインの有無にかかわらず閲覧できる。
- 新しい投稿から順に表示する。
- 各投稿に写真、キャプション（入力がある場合）、投稿日時、いいね数を表示する。
- 投稿がない場合は、そのことが分かる案内を表示する。
- 初版では一覧画面で写真を閲覧できればよく、投稿詳細画面は必須としない。

### 3.5 自分の投稿の削除

- ログインした人が、自分の投稿だけを削除できる。
- 削除前に確認を表示する。
- 他人の投稿は削除できない。
- 削除した投稿は一覧から消え、関連するいいねも削除される。
- 投稿の編集や写真の差し替えは今回含めない。



### 3.7 最初の完成版の確認項目

- 2人分のアカウントをメールアドレスとパスワードで登録できる。
- ログイン、写真投稿、一覧での確認、ログアウトができる。
- ログアウト後も投稿一覧を閲覧できる。
- キャプションなしの投稿は成功し、201文字以上の投稿はエラーになる。
- 写真なしや、許可していないファイルの投稿はエラーになる。
- 同じメールアドレスの重複登録はエラーになる。
- いいねの追加・取り消しができ、重複して数が増えない。
- 自分の投稿は削除でき、他人の投稿は削除できない。
- 未ログインでは投稿・削除・いいねを実行できない。

## 4. 余裕があれば追加する機能

- コメント：必須機能が完成した後に、追加するか検討する。今回の完成条件には含めない。

検索、フォロー、投稿編集、インターネットへの公開は今回の対象外とする。
メールアドレスの確認メールやパスワード再設定も初版には含めない。

## 5. 非機能要件

### 5.1 技術・動作環境

- Webアプリの処理にはFlask、データベース操作にはPeeweeを使用する。
- 初版のデータベースは、ローカルで扱いやすいSQLiteとする。
- 写真はローカルのアップロード用ディレクトリに保存し、データベースには保存先を記録する。
- ブラウザから操作でき、アプリを再起動してもユーザー・投稿・いいね・写真が残る。
- 大人数の同時利用や本番運用への対応は、今回の完成条件に含めない。

### 5.2 使いやすさ

- 画面やエラーメッセージは日本語で表示する。
- 写真を中心にしたシンプルな一覧とし、写真が画面幅からはみ出さないようにする。
- 登録、ログイン、投稿、ログアウトへの導線を分かりやすくする。
- エラーが起きた場合は、ユーザーが入力を直せる説明を表示する。

### 5.3 安全性

- パスワードは平文で保存せず、ハッシュ化して保存する。
- 投稿者のメールアドレスは、公開される投稿一覧に表示しない。
- 投稿・削除・いいねの認証や権限は、サーバー側で確認する。
- データを変更するフォームにはCSRF対策を行う。
- キャプションはHTMLとして実行されないように表示する。
- 秘密鍵、ローカルのデータベース、アップロードされた写真はGitに登録しない。

## 6. 実装時に注意すべきこと

### 6.1 データの関係を小さく保つ

- ユーザー、投稿、いいねの3種類を基本とする。
- 投稿は1人のユーザーに所属し、いいねはユーザーと投稿を結び付ける。
- メールアドレスの重複と、同じユーザーによる同じ投稿へのいいねの重複は、データベース側でも防ぐ。
- メールアドレスの前後の空白を除去し、登録時とログイン時で同じ扱いにする。
- 表示名やプロフィールなど、未決定の機能は追加しない。

### 6.2 写真アップロードを確認する

- 初版の実装上の既定値として、JPEG・PNGのみ、1枚5MBまでとする。
- 拡張子だけでなく、内容が読み込み可能な画像かも確認する。
- 保存ファイル名はアプリ側で重複しない名前を生成し、利用者のファイル名をそのまま保存先に使わない。
- 投稿に失敗した場合は、写真だけ、または投稿データだけが残らないように処理する。
- 投稿の削除時には、関連する写真ファイルも削除する。

### 6.3 画面表示だけに頼らず制限する

- 削除ボタンを非表示にするだけではなく、リクエストを受け取る処理でも投稿者本人か確認する。
- 必須入力、文字数、ファイル制限はサーバー側でも検証する。
- データの変更はGETでは行わず、POSTなどで受け付ける。
- 存在しない投稿や削除済みの投稿への操作では、分かりやすいエラーを返す。

### 6.4 小さく作って確認する

1. データベースとユーザー登録を作る。
2. ログイン・ログアウトを作る。
3. 写真投稿と投稿一覧を作る。
4. 自分の投稿の削除を作る。
5. いいねの追加・取り消しを作る。
6. 完成版の確認項目に沿って、2つのアカウントと未ログイン状態で動作を確認する。

各段階で正常な操作と入力エラーを確認してから次に進む。コメントより先に必須機能を完成させる。
